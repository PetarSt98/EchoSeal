EchoSeal - Algorithm Summary (July 2026 codebase)
==================================================

Goal: embed an inaudible, cryptographically verifiable watermark into speech
in real time; later, an offline detector ingests any recording (or excerpt)
and reports AUTHENTIC / TAMPERED / NO-WATERMARK, localising edits in time.


1. Frame format (rtwm/frame.py - single source of truth for TX and RX)
-----------------------------------------------------------------------
* One frame = 1215 BPSK symbols:
      63-symbol MLS preamble | 128-symbol counter header | 1024 coded bits
* 32 samples per symbol at 48 kHz -> 1.5 kBd, frame = 38 880 samples (0.81 s).
* Frames repeat back-to-back forever; each is fully self-contained, so any
  few-second excerpt holds several independently verifiable frames.
* Per frame, a hop band is chosen from {4-6, 8-10, 16-18, 18-22} kHz via
  HMAC-SHA256(band_key, ctr).  The carrier is the band centre snapped to a
  multiple of the symbol rate (integer cycles/symbol); 4th-order Butterworth
  band-pass shapes the spectrum.

2. Per-frame payload (rtwm/embedder.py, rtwm/crypto.py, rtwm/fastpolar.py)
---------------------------------------------------------------------------
* Plaintext (27 B): "ESAL" | 32-bit frame counter | 8-B session nonce | pad.
* Sealed with ChaCha20-Poly1305 -> 55 B (nonce | ciphertext | tag).
  Sub-keys (AEAD, PN, band hop) derived from the 256-bit master key via HKDF.
* FEC: CRC-8-aided polar code, N=1024, K=448, SCL decoding (5G reliability
  sequence).  Payload bits are scrambled by an AES-CTR PN stream keyed per
  frame; the header carries the low 16 counter bits under a fixed PN.

3. Real-time embedding (rtwm/embedder.py)
------------------------------------------
* process(block): mixes pre-generated frame chips into the host audio.
* Level policy per block: -20 dB below host RMS, raised toward the host's
  in-band RMS when the hop band is busy (masking), capped at -12 dB,
  clip-limited, and gated in near-silence (< -80 dBFS).
* Frame generation costs ~1 ms per 0.81 s frame (real-time with huge margin).

4. Offline detection (rtwm/detector.py)
----------------------------------------
Per band: resample to 48 kHz -> band-pass -> normalised correlation against
the (TX+RX filtered) preamble template -> coherent integrate-and-dump demod
(channel phase estimated from the preamble; polarity inversion is absorbed)
-> header majority vote gives the frame counter -> PN despread -> LLRs ->
CA-SCL polar decode with AEAD-open as validator -> decrypt, check magic and
counter, extract session nonce.

5. Verdict logic (WatermarkDetector.analyze -> Report)
-------------------------------------------------------
Decoded frames are cryptographically genuine; tampering is judged on
consistency:
  * session nonce must be identical across frames        (splice)
  * no counter may repeat                                (replay / copy-paste)
  * position deltas must equal counter deltas            (cut / insert, >=21 ms,
    including surgical removal of whole frames at exact boundaries)
  * >=2-frame holes in an otherwise healthy timeline     (same-length
    replacement, e.g. AI dub) -> unverified_spans
  * decoded frames must match their reconstructed TX waveform in ~21 ms
    windows (two-metric check)                           (sub-frame edits)
  * a single missing frame between healthy neighbours triggers
    erasure-assisted re-decoding: dead symbol runs are located by data-free
    BPSK coherence, erased, and the decoder retried; success authenticates
    the rest of the frame and pinpoints the edit.
Missing frames on a uniformly degraded channel (codec band-kill, noise) are
reported as unverified spans but are NOT tampering by themselves.

Verdicts: authentic | tampered (any issue) | no-watermark (nothing decodes:
absent mark, wrong key, or forged mark - forgery cannot pass AEAD).

6. Known limits (by design / future work)
------------------------------------------
* Detection floor: cuts/inserts >=21 ms; same-length replacements >= ~30-60 ms.
* True silence carries no watermark (silence gate): unverifiable by physics.
* Over-the-air capture (reverb, clock drift) and real codec round-trips are
  not yet validated; multiband redundancy per frame and psychoacoustic
  shaping are the designed next steps.

Tests: tests/ - unit (crypto, polar, utils, filter), component (embedder,
detector), scenario e2e (clean / cut / AI replacement / word swap).  All fast;
no test exceeds ~15 s.
